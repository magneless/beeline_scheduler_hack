# LCT Beeline — планирование выездных инженеров

Рабочее место диспетчера для распределения заявок между выездными инженерами. Сервис помогает составить план дня, увидеть загрузку команды и перестроить расписание при авариях, отменах и изменении доступности сотрудников.

## Возможности

- **Загрузка данных:** импорт заявок и реального состава бригад из CSV или выбор демонстрационного района.
- **Планирование:** распределение работ с учётом навыков, транспорта, клиентских окон, смен и запасов оборудования. Приоритет — аварии, затем подключения, ремонт и дозаказы.
- **Карта и расписание:** маршруты, занятость инженеров, назначенные заявки и причины неназначения.
- **Работа в течение дня:** новые аварии с произвольным адресом и требованиями, обычные заявки без переноса старых визитов, отмены, статусы работ и недоступность инженеров.
- **Контроль исполнения:** сохранение версий планов, истории изменений, выполненных работ и остатков оборудования.

Для демонстрационных CSV сохранены исходные строки офисов. Два адреса из источника не позволяют однозначно подтвердить нужное строение в публичном геокодере, поэтому демо явно использует проверенные канонические OSM-точки и сообщает об этом в issue `DEMO_OFFICE_OVERRIDE`; исходный адрес доступен в `office_override.original`. Обычный импорт CSV таких замен не делает и останавливается на неподтверждённом офисе.

Планирование использует OR-Tools; доступен также базовый алгоритм для сравнения. Адреса и дорожные маршруты берутся из OpenStreetMap через Photon и OSRM, отдельно для автомобиля и пешего передвижения. Для работы без сети есть явно включаемый демонстрационный режим. Публичные геосервисы рассчитаны на небольшую нагрузку; для постоянной эксплуатации настраиваются собственные серверы.

## Структура проекта

```text
backend/                  # Go-сервер и бизнес-логика
  cmd/server/             # Запуск HTTP API и фонового обработчика
  internal/               # Планировщик, планы, геоданные, импорт и PostgreSQL
  contracts/              # Общие контракты модулей
  scripts/                # Подготовка OR-Tools и запуск тестов
frontend/                 # Интерфейс диспетчера: React, TypeScript, Vite
  src/app/                # Запуск приложения, маршрутизация и провайдеры
  src/pages/              # Выбор сценария и рабочее место диспетчера
  src/features/           # Импорт, расчёт плана и действия диспетчера
  src/shared/             # HTTP API, общие компоненты и карта
datasets/original/        # Исходные наборы заявок
docs/                     # Требования, контракты и инструкции
.github/workflows/        # Автоматические проверки
compose.yaml              # Совместный запуск frontend, backend и PostgreSQL
```

## Запуск

Нужен Docker с Compose. Из корня репозитория:

```bash
cp .env.example .env
```

Задайте `POSTGRES_PASSWORD` в `.env`, затем запустите приложение:

```bash
docker compose up --build -d --wait
```

[Интерфейс диспетчера](http://localhost:3000) доступен на порту 3000, HTTP API — по адресу `http://localhost:8080/api/v1`.

После импорта заявок загрузите CSV бригад в панели «Бригады» и рассчитайте план. Шаблон доступен в интерфейсе; в демонстрационных сценариях состав уже заполнен.
