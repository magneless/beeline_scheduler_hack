# LCT Beeline — планирование выездных инженеров

Рабочее место диспетчера для распределения заявок между выездными инженерами. Сервис помогает составить план дня, увидеть загрузку команды и перестроить расписание при авариях, отменах и изменении доступности сотрудников.

## Возможности

- **Загрузка данных:** импорт заявок и реального состава бригад из CSV или выбор демонстрационного района.
- **Планирование:** сравнение двух вариантов начала дня, выбор рабочего плана, распределение работ с учётом навыков, транспорта, клиентских окон, смен и запасов оборудования. Приоритет — аварии, затем подключения, ремонт и дозаказы.
- **Карта и расписание:** спокойная подложка OpenStreetMap, отдельный маршрут выбранной бригады с номерами остановок и порядком визитов; расписание открывается по запросу.
- **Работа в течение дня:** варианты пересчёта при авариях, новых заявках, отменах и недоступности инженеров, включая допуск опоздания на аварию и вызов резервных инженеров. Диспетчер сравнивает изменения и принимает план.
- **Контроль исполнения:** сохранение версий планов, истории изменений, выполненных работ и остатков оборудования.

## Работа диспетчера

1. На экране «Подготовка рабочего дня» загрузите CSV заявок и бригад, проверьте дату и офис. Офис можно отметить на карте. После подготовки уточните нераспознанные адреса, постройте два варианта плана на одинаковых данных: в исходных окнах и с допуском опоздания на аварии. Сравните и примите один из них.
2. Откройте **«Без бригады»** в режиме **«Вместе»**: заявки и бригады видны одновременно. Выберите заявку, чтобы сравнить навыки, транспорт, остатки оборудования и смены инженеров. Совпадение этих условий ещё требует проверки дороги и расписания.
3. Выберите бригаду в **«Маршрутах»**. На карте появится её маршрут; номера точек соответствуют визитам под картой. Нажмите на визит, чтобы открыть заявку.
4. Во время смены добавляйте обращения, отмечайте начало и завершение работ, отмены и недоступность сотрудников. При событии сравните варианты на карте и в расписании и примите подходящий. Если работа закончится позже плана, сервис пересчитает оставшиеся визиты этой бригады.

Неназначенные заявки принятого плана остаются в отдельном списке с причинами. Их дальнейший разбор и перенос, передача маршрутов бригадам и уведомление клиентов выполняются вне приложения. Полный порядок действий описан в [рабочем процессе диспетчера](docs/dispatcher-flow.md).

Для демонстрационных CSV сохранены исходные строки офисов. Два адреса из источника не позволяют однозначно подтвердить нужное строение в публичном геокодере, поэтому демо явно использует проверенные канонические OSM-точки и сообщает об этом в issue `DEMO_OFFICE_OVERRIDE`; исходный адрес доступен в `office_override.original`. Обычный импорт CSV таких замен не делает и останавливается на неподтверждённом офисе.

На начальном экране доступны также шесть наборов из `datasets/additional_days` за 28 и 29 сентября 2026 года. Дата берётся из содержимого CSV: номера дней в именах файлов не определяют её порядок. В этих выгрузках нет офиса, поэтому используется демонстрационный офис района с пометкой в сценарии. Сценарий открывается для планирования с начала дня, без переноса исторических статусов заявок.

В диспетчерской можно выбрать алгоритм расчёта: оптимизированный (VROOM) или базовый (распределение по порядку заявок). Выбор применяется при построении или следующем пересчёте и сохраняется в плане. Обычные новые заявки вставляются в свободные интервалы без перестановки существующих визитов. Адреса и дорожные маршруты берутся из OpenStreetMap через Photon и OSRM, отдельно для автомобиля и пешего передвижения. Для работы без сети есть явно включаемый демонстрационный режим. Публичные геосервисы рассчитаны на небольшую нагрузку; для постоянной эксплуатации настраиваются собственные серверы.

## Структура проекта

```text
backend/                  # Go-сервер и бизнес-логика
  cmd/server/             # Запуск HTTP API и фонового обработчика
  internal/               # Планировщик, планы, геоданные, импорт и PostgreSQL
  contracts/              # Общие контракты модулей
  scripts/                # Запуск проверок с VROOM
frontend/                 # Интерфейс диспетчера: React, TypeScript, Vite
  src/app/                # Запуск приложения, маршрутизация и провайдеры
  src/pages/              # Выбор сценария и рабочее место диспетчера
  src/features/           # Импорт, расчёт плана и действия диспетчера
  src/shared/             # HTTP API, общие компоненты и карта
datasets/original/        # Исходные наборы заявок
datasets/additional_days/ # Дополнительные дни, доступные на начальном экране
docs/                     # Требования, контракты и инструкции
.github/workflows/        # Автоматические проверки
compose.yaml              # Совместный запуск frontend, backend и PostgreSQL
```

## Запуск

Нужен Docker с Compose. Из корня репозитория:

```bash
cp .env.example .env
```

Задайте `POSTGRES_PASSWORD` в `.env`, затем запустите приложение:

```bash
docker compose up --build -d --wait
```

[Интерфейс диспетчера](http://localhost:3000) доступен на порту 3000, HTTP API — по адресу `http://localhost:8080/api/v1`.

Заявки и бригады загружаются вместе на начальном экране; там же доступны шаблоны CSV. До начала событий состав можно заменить в разделе «Маршруты → Управление бригадами». Резерв формируется при принятии первого плана из доступных бригад, не получивших заданий. Дополнительные бригады не создаются. Готовые наборы открываются с явно обозначенным демонстрационным составом.
