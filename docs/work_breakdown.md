# Распределение работы

Команда: четыре Go-разработчика и один frontend-разработчик. Основа — [функциональные блоки F1–F7](functional_scope.md).

Backend — одно приложение с четырьмя внутренними модулями.

**После [Q&A 2](qa_2/QA_2_impact.md), 19.09.2026:** состав команды и основа F1–F7 сохраняются, включая перепланирование. Go-2 уточняет ВК/HD и норматив аварии; Go-1, Go-2, Go-4 и Frontend согласуют расширения для фактических статусов, приоритетов типов и оборудования. Перенос минимального учёта оборудования из D3 в основу — рекомендация из анализа; его схема ещё не включена в контракты.

| Модуль | Исполнитель | Ответственность |
|---|---|---|
| **[1. Планировщик](contracts/planner.md)** | **Go-1** | Базовый алгоритм и оптимизация: назначение инженеров, порядок посещений, расписание, учёт ограничений и причины неназначения. |
| **[2. Управление данными](contracts/data.md)** | **Go-2** | Заявки, инженеры, навыки, смены, транспорт, регионы и нормативы. Импорт, проверка, редактирование и подготовка снимка данных для расчёта. |
| **[3. Геоданные](contracts/geo.md)** | **Go-3** | Геокодирование, матрицы дорожных расстояний и времени, автомобильный и пешеходный профили, геометрия маршрутов, расчёт положения в пути и кэширование. |
| **[4. Управление планами и перепланирование](contracts/plans.md)** | **Go-4** | Последовательность обычного расчёта и обработки событий: подготовка задачи, вызов геоданных и планировщика, сохранение прошедшей части дня, проверка результата, метрики и сравнение версий. |
| **[Рабочее место диспетчера](contracts/frontend.md)** | **Frontend** | Загрузка данных, настройка инженеров, карта, расписание, карточки, неназначенные заявки, формы событий и сравнение результатов. |

**Общая инфраструктура — Go-2:** HTTP API, хранение данных и версий планов, конфигурация и сборка приложения. Go-4 определяет процесс создания нового плана, Go-2 подключает его к API и хранению.

## Взаимодействие модулей

1. Модуль управления планами получает снимок исходных данных и запрашивает географические расчёты.
2. Планировщик получает подготовленную задачу и матрицы, возвращает назначения и расписание.
3. Модуль управления планами проверяет результат, рассчитывает метрики и получает геометрию маршрутов; инфраструктура сохраняет версию и отдаёт её интерфейсу.
4. При новой срочной заявке, отмене заявки или недоступности инженера модуль управления планами фиксирует завершённые и начатые работы, обновляет условия и повторно вызывает тот же планировщик.

Планировщик работает с условиями задачи; обработка событий принадлежит Go-4. Правила допустимости плана согласовывают Go-1 и Go-4.

## Параллельная разработка и интеграция

- Сначала согласовать общие модели, единицы измерения, интерфейсы модулей и примеры входов и выходов.
- Каждый разработчик реализует свой модуль, используя заглушки зависимостей. Frontend работает с mock API по тем же контрактам.
- В контракте каждого модуля указаны как реализуемые, так и используемые интерфейсы; [общие примеры](contracts/examples/README.md) задают входы и ответы заглушек.
- Рано собрать сквозной сценарий: данные → базовый расчёт → проверка и метрики → карта и расписание. Затем подключать оптимизацию и события.
- Go-2 отвечает за сборку приложения, Go-4 — за сквозную проверку сценариев. Каждый разработчик исправляет свою часть.
