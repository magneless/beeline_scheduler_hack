# Q&A 2 — сводка

Источник: [QA_raw.md](QA_raw.md).

## Извлечённые сведения

| Тема | Информация |
|---|---|
| Подтверждение завершения | Факт закрытия заявки фиксирует диспетчер на основании информации от бригады. Закрытые заявки считаются выполненными и не включаются в дальнейшее перераспределение. |
| Статусы заявки | «Отправлено» означает поступление заявки исполнителю; «В пути» — движение бригады к месту работ. Далее заявка переходит к выполнению, а после окончания работ — в «Завершено». |
| Отмена заявки | Статус «Отменена» может появиться при отказе клиента или если бригада установила, что выполнить заявку невозможно. |
| Перепланирование | Изменение плана в течение рабочего дня допускается. При этом необходимо учитывать приоритеты разных типов работ. |
| Приоритеты типов работ | Подключение может иметь более высокий приоритет, чем ремонт. Аварийная заявка может потребовать оперативного изменения текущего маршрута. |
| Время визита и клиент | При изменении расписания ранее озвученное клиенту время может быть скорректировано. С клиентом связывается служба поддержки. |
| Недостающие данные | Если в исходном наборе нет необходимых характеристик бригад, команда может самостоятельно смоделировать компетенции и транспорт. |
| Модель компетенций | Компетенции можно определить через типы работ, которые разрешено выполнять бригаде. Квалификация для ремонтов или аварийных работ может быть только у части бригад. Дополнительные компетенции и уровни команда вводит по своему усмотрению. |
| Ограничение квалификации | Заявка не должна назначаться бригаде, у которой отсутствует необходимая квалификация для соответствующего типа работ. |
| Выдача оборудования | Бригада получает оборудование в офисе сразу на весь рабочий день. Допустимый запас команда может определить самостоятельно в рамках модели. |
| Оборудование при перепланировании | На бригаду можно назначить только заявки, для выполнения которых у неё есть необходимое оборудование. |
| Норматив аварии | Для расчётов следует использовать норматив выполнения аварийной заявки 100 минут. |
| Поступление аварии | Начало выполнения аварийной заявки определяется временем её фактического поступления. Авария возникает в течение рабочего дня и может повлиять на дальнейшее расписание бригады. |
| ВК и HD | ВК относится к Beekeeper, HD — к HelpDesk, сторонней системе поступления заявки. Это обозначения разных систем, а не два разных вида работ. |
| Классификаторы заявок | Поля «тип заявки ВК» и «тип заявки HD» могут содержать разные классификаторы одной заявки. Команда может определить соответствие между ними на основе предоставленных данных. |
| Статическое и динамическое планирование | Для хакатона достаточно построить статическое расписание по исходной выгрузке. Динамическое перепланирование в течение дня допускается как дополнительная возможность. |
