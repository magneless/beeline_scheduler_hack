# Геоданные — Go-3

Владеет координатами, дорожными расчётами и геометрией. Потребители — Go-2 при импорте и Go-4 при планировании. Go-1 получает готовую матрицу. [Общие типы](common.md).

## Реализует

Go-3 реализует `GeoService` и типы запросов/результатов ниже. Внутреннюю реализацию провайдера маршрутов, геокодирования и кэша Go-3 выбирает сам; отдельный внешний контракт для провайдера не требуется.

```go
type GeoService interface {
    Geocode(ctx context.Context, input GeocodeRequest) (GeocodeResult, error)
    BuildMatrix(ctx context.Context, input MatrixRequest) (TravelMatrix, error)
    BuildRoutes(ctx context.Context, input RoutesRequest) (RoutesGeometry, error)
    PositionAt(ctx context.Context, input PositionRequest) (PositionResult, error)
}
```

## Использует

Из других модулей прямых вызовов нет. На вход принимает общие `Location`, `Point`, `Transport`, `Leg` и `Issue` из [common.md](common.md). Результаты используют Go-2 для нормализации адресов и Go-4 для подготовки расчёта, добавления геометрии и определения положения при событии. Go-1 получает матрицу через Go-4.

Для старта используйте примеры `geocode_request`/`geocode_result`, `matrix_request`/`matrix`, `routes_request`/`routes_geometry` и `position_request`/`position_result` в [examples/backend_flow.json](examples/backend_flow.json). Фиксированные расстояния, времена и полилинии в примере — тестовые данные для локальной заглушки, а не требование к конкретному дорожному провайдеру.

## Форматы

| Тип | Поля |
|---|---|
| `GeocodeRequest` | `region_id`, `locations: LocationInput[]` |
| `GeocodeResult` | `items: [{location_id, location: Location?, issue: Issue?}]` |
| `MatrixRequest` | `locations: Location[]`, `profiles: Transport[]`, `geo_context_id: string?` |
| `TravelMatrix` | `id`, `geo_context_id`, `location_ids: string[]`, `profiles: map[Transport][][]TravelCell` |
| `TravelCell` | `reachable: bool`, `duration_sec: int64?`, `distance_m: int64?` |
| `RoutesRequest` | `geo_context_id`, `locations: Location[]`, `legs: [{leg_id, from_location_id, to_location_id, profile}]` |
| `RoutesGeometry` | `items: [{leg_id, geometry: Point[]}]` |
| `PositionRequest` | `leg: Leg`, `at` |
| `PositionResult` | `point: Point`, `elapsed_duration_sec`, `elapsed_distance_m`, `elapsed_geometry: Point[]` |

`geo_context_id` фиксирует дорожные данные и настройки транспортных профилей. ID матрицы фиксирует конкретный набор точек и результат расчёта. Новая матрица может использовать тот же географический контекст.

## Матрица и геометрия

- Ячейка `[i][j]` означает путь от `location_ids[i]` к `location_ids[j]`. Один порядок используется во всех профилях; размер каждой матрицы — N × N.
- Расчёт направленный: A → B не обязан совпадать с B → A.
- Достижимая ячейка содержит время и расстояние. У недостижимой оба значения `null`. Диагональ достижима с нулевыми значениями.
- Все запрошенные профили должны присутствовать. Отсутствие профиля или сбой провайдера — ошибка всего вызова, а не недостижимость всех пар.
- `BuildRoutes` получает уже выбранные участки, не меняет порядок посещений и не пересчитывает расписание. Геометрия строится в том же контексте, что и матрица.
- Если геометрия хотя бы одного запрошенного участка недоступна, вызов завершается ошибкой с `leg_id`; частичный результат не выдаётся как полный.

## Положение при событии

`PositionAt` работает по сохранённой геометрии и времени участка. До начала возвращает начало и нулевой пройденный путь; после конца — конец и полный путь.

Внутри участка для демо принимается равномерное продвижение по длине полилинии за плановую длительность. Пройденные метры — соответствующая доля сохранённого `distance_m`. Округление и остаток должны сохранять исходную сумму. Участок нулевой длительности считается завершённым в `end_at`.

Это модельное положение. Go-4 сохраняет пройденный отрезок и создаёт новую стартовую точку для будущего маршрута.

## Ошибки и самостоятельная разработка

На каждый вход геокодирования возвращается один элемент с координатами либо `issue`. Неоднозначный адрес не выбирается молча. Некорректные координаты и неизвестные ID — `INVALID_INPUT`; техническая недоступность или невозможность воспроизвести контекст — `GEO_UNAVAILABLE`.

Для разработки используются подготовленные адреса, точки и последовательности участков. Импорт CSV, назначение инженеров, хранение планов и HTTP находятся за границей модуля.
