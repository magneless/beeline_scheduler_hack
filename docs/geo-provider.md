# Геоданные OpenStreetMap

По умолчанию `GEO_PROVIDER=osm`: Photon ищет адреса, OSRM строит маршруты по дорожной сети. Для автомобиля и пешего передвижения используются отдельные серверы. Ошибка провайдера возвращается как `GEO_UNAVAILABLE`; прямые линии вместо дорог не подставляются.

| Переменная | Значение по умолчанию |
| --- | --- |
| `GEO_PHOTON_URL` | `https://photon.komoot.io` |
| `GEO_OSRM_CAR_URL` | `https://routing.openstreetmap.de/routed-car` |
| `GEO_OSRM_FOOT_URL` | `https://routing.openstreetmap.de/routed-foot` |
| `GEO_USER_AGENT` | имя и адрес репозитория приложения |
| `GEO_MIN_INTERVAL_MS` | `0`; для публичных серверов минимум `1000` действует автоматически |
| `GEO_CACHE_DIR` | `.cache/geo`; в Compose — `/var/cache/scheduler` |

Ответы сохраняются на 24 часа, кэш ограничен 512 файлами и 64 МиБ. В Compose он переживает перезапуск благодаря volume `geo_cache`. Очереди Photon и OSRM независимы; медленная маршрутизация не задерживает поиск адресов. Публичные endpoints получают не больше одного запроса в секунду на сервер; запросы отменяются по контексту и имеют HTTP timeout 20 секунд на попытку. При временных сетевых сбоях, HTTP 408/429/500/502/503/504 выполняется до трёх попыток с паузами 0,5 и 1 секунду; ограничение частоты действует и на повторы. Заголовок `Retry-After` учитывается до 30 секунд; более длительное ожидание завершает запрос ошибкой без раннего повтора. Отмена расчёта прерывает ожидание. TLS handshake ограничен 15 секундами. Если попытки исчерпаны, API возвращает понятный `GEO_UNAVAILABLE`, техническая причина остаётся в серверном журнале. Интерфейс сохраняет сообщение с кнопкой «Повторить расчёт» и ранее построенный план. Матрица использует Table API с `duration,distance`, максимум 100 координат на запрос. Недоступное направление сохраняется как `null`, не заменяется оценкой расстояния. Геометрия запрашивается для назначенных поездок.

Поиск адреса не ограничен успешным разбором регулярными выражениями: любой непустой ввод доходит до Photon. Нормализованная строка, структурированный запрос по базовому номеру и исходная строка дают до 50 кандидатов за запрос. Полный номер дома проверяется после поиска, включая корпус, строение и дробь. Дубли одного здания объединяются; отдельные здания с одинаковым адресом требуют выбора.

Нераспознанные валидные заявки сохраняются и видны диспетчеру с причиной. Кнопка «Уточнить адрес» позволяет исправить строку, выбрать найденный дом, отметить точку на карте или ввести координаты. До первого расчёта подтверждение возвращает заявку в исходный набор; при действующем плане открывает расчёт вариантов её включения. ID, тип работы, оборудование и окно исходной заявки сохраняются. Для новых обращений в форме доступна кнопка «Указать дом на карте»: выбранные координаты передаются в расчёт без геокодирования. Координаты не выдумываются, `корпус` и `строение` не подменяются автоматически. Подробнее — [контракт геоданных](contracts/geo.md).

Одинаковые адреса внутри импорта запрашиваются один раз. При временной недоступности Photon найденные результаты сохраняются, остальные заявки остаются доступными для уточнения; один сбой не уничтожает весь импорт.

Публичные сервисы подходят для небольших демонстраций и не гарантируют доступность. Для больших импортов и постоянной работы можно развернуть собственные Photon/OSRM и заменить URL: платные API и ключи не нужны, но нужны ресурсы машины. Для собственных endpoints секундная задержка не навязывается; дополнительный интервал настраивается через `GEO_MIN_INTERVAL_MS`. Пешеходный OSRM должен быть подготовлен с foot-профилем; смена строки `driving` в URL автомобильного сервера не создаёт пешеходную сеть. Пробки не учитываются. Интерполяция текущей позиции основана на плане, а не на GPS.

`GEO_PROVIDER=demo` явно включает синтетические координаты и прямые линии для офлайн-тестов; в план добавляется `DEMO_GEO`. Демонстрационные данные заявок и бригад выбираются отдельно от геопровайдера.

Фоновая карта по умолчанию — MapLibre GL со светлым векторным стилем `https://tiles.openfreemap.org/styles/positron` на данных OpenStreetMap; API-ключ не нужен. Основная карта и выбор адреса используют один движок, русские подписи и номера домов при приближении. Для отображения нужен WebGL2. При недоступности фоновой карты заявки и маршруты остаются видимыми, фон можно загрузить повторно. На ней отображаются офис, заявки и дорожная геометрия поездок. Карту можно перемещать и масштабировать, нажатие на заявку выбирает её в рабочем пространстве. Источники карты доступны в стандартном блоке атрибуции MapLibre. Координаты выбранного дома можно уточнить перетаскиванием метки; изменение текстового адреса сбрасывает старую точку.

Плитки загружаются браузером по мере просмотра, без массового скачивания или предзагрузки. Применяются [условия сервера плиток OSM](https://operations.osmfoundation.org/policies/tiles/); для высокой нагрузки нужен отдельный поставщик плиток. При недоступности фона координаты заявок и маршруты сохраняются, интерфейс предлагает повторить загрузку. Геокодирование, маршрутизация и фоновая карта — отдельные запросы; `GEO_PROVIDER=demo` не делает фон доступным без интернета.

Источники: [Photon](https://github.com/komoot/photon), [OSRM API](https://project-osrm.org/docs/v5.24.0/api/), [условия публичных серверов FOSSGIS](https://routing.openstreetmap.de/about.html).
